# Security policy

## Supported versions

Security fixes are developed on the active `0.1.x` line until a supported
release policy is published.

## Reporting a vulnerability

Do not disclose vulnerabilities through public issues. After the repository
administrator enables GitHub private vulnerability reporting in **Security >
Reporting**, use the repository's **Report a vulnerability** option. Include a
reproducible description, affected versions, impact, and any proof of concept
that does not contain production data or credentials.

Until private vulnerability reporting is enabled, do not publish the report.
Use a mutually agreed private channel with the repository owner instead.

Clarus must never be used to bypass GLPI Ticket authorization or to execute
Ticket business-rule actions during inspection.
